# 입금 모니터

카카오뱅크 입금 알림(안드로이드)을 서버로 보내 웹 대시보드에 실시간으로 표시합니다.
은행 계정에 로그인하지 않고, 폰에 뜬 알림 문구만 사용합니다.

```
카카오뱅크 → 폰 알림 → Tasker/MacroDroid → POST /api/notify → DB → 대시보드(SSE 실시간)
```

## 서버 실행 (Node.js 22.13+, 의존성 없음)

```bash
API_TOKEN=$(openssl rand -hex 24) npm start     # 토큰은 따로 적어 둘 것
```

| 환경변수 | 설명 |
|---|---|
| `API_TOKEN` | (필수) 폰이 알림을 보낼 때 쓰는 토큰 |
| `VIEW_TOKEN` | 대시보드 접속 토큰. 없으면 `API_TOKEN`과 동일 |
| `PORT` | 기본 3000 |
| `DB_PATH` | 기본 `./deposits.db` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | 설정하면 입금 시 텔레그램 알림 |

브라우저에서 `http://서버주소:3000` 접속 후 토큰을 입력합니다.
**외부 공개 시 반드시 HTTPS(예: Caddy, Cloudflare Tunnel) 뒤에 두세요.**

## 폰 설정 A: 전용 앱 (권장)

`apk/deposit-monitor.apk` 를 폰에 설치합니다(출처를 알 수 없는 앱 설치 허용 필요, 디버그 서명 APK).
소스는 `android/` 에 있고 `cd android && gradle assembleDebug` 로 직접 빌드할 수 있습니다(JDK 17+, Android SDK 34).

1. 앱 실행 → 서버 주소와 `API_TOKEN` 입력 → **저장 후 연결 테스트** ("연결 성공 ✅" 확인)
2. **1) 알림 접근 허용 설정 열기** → "입금 모니터" 켜기
3. **2) 배터리 최적화 설정 열기** → 입금 모니터를 "제한 없음/최적화 안 함"으로
4. 카카오뱅크 앱의 입금 알림이 켜져 있어야 합니다.

앱은 두 화면으로 구성됩니다.
- **목록**: 서버의 웹 대시보드가 그대로 들어 있습니다(리스트, 검색, 주문 확인, 입금 처리, 메모). 토큰을 한 번 설정하면 로그인 없이 열립니다.
- **설정**: 서버 주소/토큰, 푸시 켜기/끄기, 알림 접근 허용, 배터리 최적화.

**푸시 알림**(Firebase 없이 서버와 실시간 연결을 유지하는 방식): 새 입금이 들어오면 `💰 입금 35,900원 · 처리 필요`
(쇼핑몰 주문과 이름/금액이 일치하는지 함께 표시), 처리하면 같은 알림이 `✅ 처리 완료 · 주문 …`으로 바뀝니다.
연결을 유지하려고 상태 표시줄에 "실시간 연결됨" 알림이 계속 떠 있고, 끊긴 사이 놓친 알림은 다시 연결될 때 따라잡습니다.
Android 13 이상은 알림 권한을 허용해야 하고, 폰을 다시 켜면 자동으로 이어집니다.

앱은 카카오뱅크(`com.kakaobank.channel`) 알림만 읽어 서버로 보냅니다. 서버에 연결이 안 되면 대기열에 쌓아 두었다가
30초마다 재전송합니다. 화면 하단 로그에 수신한 알림 원문이 남으므로, 서버가 인식하지 못하면 그 문구로 `parser.js` 를 맞추세요.

## 폰 설정 B: MacroDroid (앱 없이)

1. MacroDroid 설치 후 "알림 접근 허용" 켜기, 배터리 최적화에서 MacroDroid 제외
2. 매크로 만들기
   - 트리거: **알림 수신** → 앱: 카카오뱅크 선택
   - 동작: **HTTP 요청**
     - 방식 POST, URL `https://서버주소/api/notify`
     - 헤더 `Authorization: Bearer <API_TOKEN>`
     - 본문(JSON): `{"title":"{not_title}","text":"{not_text}"}`
3. 카카오뱅크 앱의 입금 알림이 켜져 있어야 합니다.

## 테스트

```bash
curl -XPOST localhost:3000/api/notify -H "Authorization: Bearer $API_TOKEN" \
  -d '{"title":"카카오뱅크","text":"입금 50,000원 홍길동 잔액 1,234,000원"}'
npm test
```

## 알림 문구가 다를 때

실제 알림 문구가 `parser.js` 예상 형식과 다르면 금액·입금자가 인식되지 않습니다.
실제 알림 문구(계좌번호와 이름은 가리고)를 `test/parser.test.js`에 추가하고 `parser.js`를 맞추세요.
같은 알림이 같은 분에 여러 번 와도 한 번만 저장됩니다.

## 쇼핑몰(그누보드5) 주문 연동

입금 내역 옆의 **주문 확인** 버튼으로, 입금자명과 금액이 모두 일치하는 미입금 주문(`g5_shop_order`)과
그 장바구니 상품(`g5_shop_cart`)을 보여 주고, 관리자가 **주문완료(입금 처리)** 를 누르면 DB에 반영합니다.

설정(서버의 `/etc/deposit.env`, 비밀번호는 저장소/채팅에 올리지 마세요):

```
ADMIN_TOKEN=...            # install.sh 가 자동 생성. 주문 조회/처리 권한
SHOP_DB_HOST=127.0.0.1     # 그누보드 data/dbconfig.php 의 G5_MYSQL_* 값
SHOP_DB_PORT=3306
SHOP_DB_USER=...
SHOP_DB_PASSWORD=...
SHOP_DB_NAME=...
SHOP_TABLE_PREFIX=g5_
```
```
SHOP_CURRENCY=USD          # 기본 USD(달러 쇼핑몰). 금액이 원화면 KRW
SHOP_USD_KRW=              # 비우면 환율을 자동으로 찾음: 쇼핑몰 DB → 쇼핑몰 사이트 상품 페이지(exchange_rate). 직접 지정도 가능
SHOP_URL=https://ameyokovip.com   # 상품 이미지/상품보기 링크의 기준 주소
```
설정 후 `sudo systemctl restart deposit`.

**자동 처리**: 입금이 들어왔을 때 입금자명과 금액이 쇼핑몰의 미입금 주문 **한 건**과 **정확히 같으면**(허용 오차 없음) 사람이 누르지 않아도 입금 처리합니다.
후보가 없거나 여러 건이거나 금액이 조금이라도 다르면 자동 처리하지 않고 "처리 필요"로 남깁니다. 이 기능을 켜기 전에 이미 들어와 있던 입금은 건드리지 않습니다(`AUTO_PROCESS_BACKFILL=1` 이면 포함).
주문이 입금보다 늦게 생긴 경우를 위해 1분마다 미처리 입금을 다시 확인합니다(`AUTO_SWEEP_MS`). `AUTO_PROCESS=0` 으로 끌 수 있습니다.
처리 종류 뱃지: **자동처리**(시스템) / **일치처리**(관리자가 일치 건을 확인하고 처리) / **수동처리**(사유 입력) / **기처리**(쇼핑몰에서 이미 처리된 주문과 연결).

**입금 처리 시 쇼핑몰에 기록되는 것**(그누보드 관리자의 입금 처리와 같은 결과)
- 주문 `od_status` = `입금`(기본, `SHOP_STATUS_PAID` 로 변경 가능), `od_receipt_price` += 미수금, `od_misu` = 0, `od_receipt_time` = 처리 일시(한국시간)
- 장바구니 `ct_status` = `입금`
- 상점메모 `od_shop_memo`(관리자 주문 화면에 표시)에 한 줄 추가: `[입금모니터 2026-10-28 19:01:24] 입금 강애진 86,400원 확인 → 입금 처리: 사유`
- 점검 페이지 `/shop-check?token=접속토큰`: 쇼핑몰이 쓰는 상태 값과, 쇼핑몰 관리자가 직접 처리한 주문 vs 이 모니터가 처리한 주문의 DB 값을 나란히 보여 줍니다.

목록은 기본적으로 **처리 완료된 입금을 숨기고**, 오른쪽 위 `처리완료만 보기`를 켜면 그것만 보여 줍니다.

**달러 쇼핑몰의 금액 일치**: 고객이 입금해야 하는 원화는 `ceil(미수금(USD) × 환율 / 100) × 100`(100원 단위 올림)입니다.
입금액이 이 값과 ±100원 안이고 입금자명이 같으면 "이름·금액 일치"로 봅니다. 오른쪽 패널에 달러 금액, 환율 계산 금액, 차액,
상품 이미지, `상품보기`(쇼핑몰 상품 페이지, 새 창)가 표시됩니다. `SHOP_DB_NAME` 또는 `ADMIN_TOKEN` 이 없으면 이 기능은 꺼져 있습니다.

- **매칭 기준**: `od_status='주문'` 이고 `od_misu`(미수금) = 입금액, 입금자명(`od_deposit_name`, 비어 있으면 `od_name`) = 입금자(공백 무시)
- **처리 내용**(그누보드 관리자의 입금 처리와 같은 결과): `od_status='입금'`, `od_receipt_price += 입금액`, `od_misu -= 입금액`,
  `od_receipt_time=NOW()`, 해당 주문의 장바구니 `ct_status='입금'` (한 트랜잭션)
- 후보에 없는 주문은 처리할 수 없고, 한 입금은 한 주문에만, 한 주문은 한 입금에만 연결됩니다.
- **주의**: SQL로 직접 바꾸므로 그누보드 관리자 화면의 부가 동작(재고·포인트·SMS·메일 등)은 실행되지 않습니다.
  운영 DB에 적용하기 전에 백업하고, 소액 주문으로 먼저 확인하세요.
- 쇼핑몰 DB 계정은 `g5_shop_order`, `g5_shop_cart` 에 SELECT/UPDATE 권한만 주는 것을 권장합니다.

## 푸시 테스트

폰에서 앱의 **설정 > 푸시 테스트** 버튼, 또는 브라우저에서 아래 주소를 열면 테스트 푸시가 나갑니다(입금 기록은 생기지 않음).

```
http://서버주소:3100/push-test?token=접속토큰
```
열린 화면에서 `처리 필요(일치/이름만/주문 없음)`, `처리 완료`, `처리 완료·수동` 예시를 누르거나, 입금자·금액·일치 수준을 직접 정해 보낼 수 있습니다.
제목 앞에 `[테스트]`가 붙어 실제 알림과 구분됩니다. 접속 토큰이 들어 있는 주소이므로 다른 사람에게 공유하지 마세요.

## 화면 구성

- **그래프**: 합계 카드 아래에 조회 기간에 맞춘 막대 그래프(하루=시간별, 2~92일=일별, 그 이상=월별, 기간 없음=최근 30일). 막대 위에 금액, 초록=처리완료/파랑=미처리. 일별 막대를 누르면 그날만 조회됩니다.
- **웹(넓은 화면)**: 처리 완료 행에 상품 이미지, 옵션(한 줄씩), 입금/주문/처리 일시, 금액 아래에 처리 방식 뱃지와 달러·적용환율을 보여 줍니다.
- **앱**: 행은 이름·입금 시각·금액·처리 방식만 보이고, 누르면 오른쪽 상세 패널(이미지, 옵션, 일시, 달러·환율, 메모)이 열립니다. 앱이 `/#token=…&app=1` 로 열어 이 모드가 켜지며, 브라우저에서는 `?compact` 로 확인할 수 있습니다.

## iPhone 푸시 (APNs)
iPhone 앱(`ios/`)을 쓰려면 서버 환경변수 `APNS_KEY_PATH`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC`(앱 Bundle ID)을 설정합니다. 앱이 `POST /api/apns/register` 로 기기 토큰을 등록하고, 새 입금·처리 완료·푸시 테스트 때 서버가 APNs 로 보냅니다. 자세한 절차는 [ios/README.md](ios/README.md).

## 수집 방식: 카카오뱅크 입금 문자 (앱 v1.6~)
안드로이드 앱은 기본으로 **카카오뱅크 입금 문자(SMS/LMS)** 를 문자 앱 알림에서 읽어 서버로 보냅니다. 카카오뱅크 앱을 켜 두면 앱 알림이 생기지 않아 입금을 놓치는 문제를 피하기 위해서입니다.
- 카카오뱅크 앱 → 더보기 → 앱설정 → 입출금/카드결제 알림 → **SMS** 를 이 폰 번호로 신청해야 합니다(유료).
- 문자 앱이 예전 문자를 묶어 다시 올려도, 본문 시각이 15분 이내인 문자만, 한 번씩만 보냅니다.
- 설정 탭의 "카카오뱅크 입금 문자로 받기"를 끄면 예전처럼 카카오뱅크 앱 알림으로 받습니다.
- iPhone(1cent) 은 단축어 자동화(메시지에 '카카오뱅크' 포함 → `POST /api/notify?token=…`, JSON `text`=메시지 내용)로 같은 문자를 보냅니다.
